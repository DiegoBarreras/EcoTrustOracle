# Modelo B2B de micropagos con x402 (planeado, no implementado)

**Estado:** el backend actual NO cobra. Este documento describe cómo EcoTrust Oracle lo haría con [x402](https://x402.org) para la demo y el pitch. Los nombres exactos de headers y campos deben verificarse contra la guía oficial para vendedores (https://docs.x402.org/getting-started/quickstart-for-sellers) antes de implementar: x402.org solo documenta el flujo a alto nivel y esos detalles no se pudieron confirmar. El dominio `payments.org` mencionado en el brief no se pudo verificar y no se usó.

## Por qué x402 encaja

Cada auditoría es una operación discreta con costo marginal casi nulo (una tx Memo en Solana cuesta ~5000 lamports = 0.000005 SOL, más la llamada a Gemini). Cobrar por auditoría, sin cuentas ni API keys, evita el onboarding de un SaaS clásico. x402 usa el código HTTP 402 *Payment Required* para eso y soporta Solana.

## Flujo propuesto

1. El cliente (ERP, gateway IoT o agente) llama `POST /api/v1/audit-meter` o `/api/v1/audit-sensor` sin pago.
2. El servidor responde `402 Payment Required` con los requisitos de pago: red (`solana-devnet`), activo, monto y dirección de cobro.
3. El cliente firma el pago con su billetera y reintenta la misma petición adjuntando la prueba de pago en un header.
4. El servidor valida (y liquida) el pago, normalmente a través de un *facilitator* de x402, y ejecuta el pipeline: visión → hash SHA-256 → ancla Memo → Telegram.
5. Respuesta `201` con el `AuditResponse` actual.

## Precio

| Opción | Monto por auditoría | Comentario |
|---|---|---|
| Recomendada | 0.05 USD en USDC | Precio estable para presupuestos B2B; x402 está pensado para stablecoins. |
| Alternativa | 0.001 SOL | Más simple en Devnet, pero el precio en USD varía. |

Referencia de margen: el costo on-chain por auditoría es ~0.000005 SOL, mucho menor que cualquiera de los dos precios. El costo real dominante es la inferencia de visión (los sensores IoT que usan `/audit-sensor` no la consumen, así que podrían tener un precio menor).

## Plan de implementación

- Un middleware FastAPI sobre `/api/v1/audit-meter` y `/api/v1/audit-sensor` que devuelva 402 si falta el header de pago y verifique contra el facilitator si está presente. `/health`, `/docs` y `/api/v1/audit-meter-mock` quedan libres para la demo.
- Configuración en `core/config.py`: `X402_ENABLED` (false por defecto, para no romper la demo ni los tests), `X402_PAY_TO`, `X402_PRICE_USD`, `X402_NETWORK`.
- Frontend: reintentar tras el 402 firmando con la billetera Phantom/Solflare ya conectada.
- Riesgo a cerrar antes de producción: idempotencia. Un pago no debe poder reutilizarse para varias auditorías ni cobrarse si el pipeline falla antes de anclar.
